## Description

Addressed chat that the grammar doesn't match goes to terva, using the
integration chosen in the spike. docs/BRIDGE-PROTOCOL.md section 9.

## Acceptance criteria

- [x] The persona is configurable
- [x] The model gets a short state summary and recent chat, never the raw streams
- [x] At most one proposed task, and it passes owner, allowedTasks and argument checks
- [x] Per-player cooldown and a daily token cap; on failure the bot says "Hm?"

## Summary

internal/voice implements chat.Voice through the terva SDK (see the spike TKT-01M61T36F). It builds a fresh runtime per reply, in an empty temp working directory, with NoTools, MaxSteps 2 and Yolo. The tools are the allowed tasks minus say, and they only record: the first proposal wins and later ones get IsError. A non-owner gets no tools and a prompt that says so. The prompt carries the status summary and the last 20 chat lines, never the raw streams. The persona is configurable (llm.persona). Provider, model and key env come from llm.terva, and llm.terva.tervaHome isolates the bot from the machine's AGENTS.md, skills and lore. The per-player cooldown lives in chat.Brain; the daily token cap is counted from rt.Cost() and resets each local day. Any failure makes the bot say "Hm?". Smoke-tested 2026-10-28 with cmd/fakeplugin against the workstation's terva config (openai-codex): a free-form question got an in-character reply, and "give me a wave" produced an emote proposal that passed the checks and reached the plugin as a task.
